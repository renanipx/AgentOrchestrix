# RULES — Phase 1: Planner Agent

- **Rigid Analysis:** Base the requirements strictly on the consolidated decisions from Phase 0 (`goal.md` and `state.json`).
- **Functional Scope:** Define *what* must be built. Do not decide on database modeling, technical architecture, or file divisions (this belongs to the Architect).
- **Guided Planning (Skills):** You are required to read [spec-driven-planning.md](../../skills/spec-driven-planning.md) to learn how to break requirements down into atomic tasks with verification criteria.
- **No Code:** Prohibited from creating code in `generated/` or modifying project files.
- **Destructive Flows Analysis:** The Planner MUST include explicit requirements for each system entity deletion operation, specifying safeguards (e.g., confirmations, archiving, or impact on sub-elements) to prevent accidental data loss.
- **Empty State Requirements:** For each listable collection, search, or filter, the Planner MUST specify interface behavior if there are no items to display (empty state).
- **Complex Interaction Requirements:** For interactions involving gestures or compound flows, the Planner MUST specify event distinction rules, expected visual feedback, and alternative accessibility.
- **Filter and Sorting Behavior:** If the application combines search/filtering with manual reordering features, the Planner MUST explicitly define the business rules for reordering items under a filtered state.
- **Decomposition of Compound Interactions:** If `"complex_interactions"` is populated in `interview_decisions` within `state.json`, the Planner MUST create distinct sub-requirements for **each identified interaction level**, ensuring that `task.md` explicitly covers: (1) the expected behavior of each level independently; (2) the isolation rule between levels — how the system ensures that interaction at one level does not interfere with interaction at another (e.g., how to distinguish a click on a child item from a click on the parent container, how to separate dragging an inner element from dragging the outer container, how to isolate event handlers between levels of a nested menu); (3) the expected visual feedback and accessibility for each level. Without individual sub-requirements for each level and its isolation rule, the item cannot be marked as fully specified and the transition to Phase 2 is blocked.
